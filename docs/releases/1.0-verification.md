# Draft 1.0 verification

Desktop packages were built by GitHub Actions run `36996287852`, from commit `92cc1fa` and tag `v1.0.0-draft.1`. Windows and both macOS architectures built successfully; interactive installation on those operating systems has not been verified here. The release remains a draft.

Later, [run `37043500352`](https://github.com/Zajfan/DevTrack/actions/runs/37043500352)
passed Windows MSI installation/visible-window launch/uninstall and macOS
Intel/Apple Silicon DMG launch smoke checks. Its workflow commit was `9a3f5b0`;
packages were built from the draft tag. This is historical package evidence,
not verification of later source changes or complete desktop workflows.

The Desktop Verification workflow defines native workflow, restart, database
migration and production package checks against the checked-out commit. See
[coverage and reproduction](../desktop-verification.md).

[Run `38496426371`](https://github.com/Zajfan/DevTrack/actions/runs/38496426371)
on commit `9ce0bc1` passed all seven jobs: native workflow checks on Ubuntu
22.04, Windows Server 2022, macOS 15 Intel and macOS 15 Apple Silicon, and
production package builds on Windows, macOS Intel and macOS Apple Silicon.
Covered checks include schema migration, project CRUD, file/README preview,
local Git history, task version editing, Unicode notes, persistence across
two restarts, and repository relocation. Issues [#3](https://github.com/Zajfan/DevTrack/issues/3)
and [#4](https://github.com/Zajfan/DevTrack/issues/4) are closed on this
evidence. Remaining gaps are documented in [desktop-verification.md](../desktop-verification.md).

The Linux AppImage initially failed on Fedora because its bundled Wayland libraries conflicted with the host graphics stack. `scripts/repair-appimage.py` removes those four libraries while retaining the AppImage runtime, filesystem contents and permissions. The repaired draft asset passed startup, project creation, folder selection, files/README, completed-work filters, planned tasks, version sorting/persistence, and exact clickable-tag checks.

Reproduce the packaged Linux checks with:

```sh
DEVTRACK_SKIP_SCREENSHOTS=1 xvfb-run -a python3 scripts/test-desktop.py /path/to/DevTrack_1.0.0_linux_amd64.AppImage
```

The screenshot flag handles the host WebDriver differing from bundled WebKit; it skips only image capture. Native Linux binary checks also passed with screenshots enabled. All tests use temporary application data.

Companion browser tests passed at phone and tablet widths, covering tasks, prerelease versions, notes, tags, GitHub filtering/caching, validated JSON transfer, and preservation of unreadable saved data. Target-based design comparison was run against the original Projects, Planned, Notes and Transfer designs. Planned passed the DOM coverage threshold; the other comparisons reported low overlap. The source designs contain a phone within a larger artboard, so automatic font and coordinate deltas were unsuitable for direct application. Phone screenshots were inspected independently; working controls and legible touch targets were retained.

Android workflow `37001560762`, from commit `41a6bb7`, passed browser checks, release compilation, lint, offline Android 15 emulator persistence, and installation/launch of the signed release APK. Android 8 is the declared minimum; emulator verification used Android 15. The stable self-generated signing key is excluded from git and configured in CI secrets.

Native iOS is pending by request. Native HarmonyOS requires a separate port and SDK/signing setup. Neither is represented by an Android APK or a web app.
